# research/：每天看一点，别抄一句

这个目录是给**素材**用的，不是给卡片用的。卡片在 `data/`，素材在这里。

为什么分开：卡片是「已经想清楚的情境」，素材是「还没想清楚但看起来有用的一句话、一个评论区现象、一次吵架的完整过程」。混在一起，卡片库会被半成品污染。

## 每天做什么（十分钟）

```bash
python scripts/intel.py                   # 先看今天的简报：检索词 + 每个词现在命中的卡 + 缺口
python scripts/harvest.py plan            # 只要检索词
# 用你的搜索工具（Claude/Codex/DSH 的联网搜索，或自己搜）搜这三组
# 挑 2-3 篇没看过的，读完
python scripts/harvest.py check           # 写完了校验 + 查重
python scripts/harvest.py promote hb-0007 # 值得进库的，出卡片骨架
```

`plan` 按日期轮转 12 组检索词，`plan_groups()` 会跳过最近 14 天已经搜过的主题——所以你不会连着三天都在看「已读不回」。`intel.py` 是 `plan` 加一层对照：每个检索词都跑一遍检索，后面跟着它现在命中的卡和分数，分数低于提示线的单列进「库里可能缺的」。日报里那条评论就是它生成的，本地先跑一遍和线上看到的是同一份。

## 候选写在哪

`research/inbox/<日期>.jsonl`，一行一条。字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✔ | `hb-0001` 起，四位数字，全库不重复 |
| `date` | ✔ | `YYYY-MM-DD`，你看这条的日期 |
| `platform` | ✔ | `xiaohongshu` / `douyin` / `zhihu` / `douban` / `weibo` / `bilibili` / `news` / `other` |
| `url` | ✔ | 原文地址，必须能点回去 |
| `title` | ✔ | 你看到时的标题 |
| `scene_guess` | ✔ | 10 个场景之一；拿不准就写最接近的，转卡时还能改 |
| `situation` | ✔ | 10-80 字，**用你自己的话**说清这个情境 |
| `gap` | ✔ | 6-60 字，现有 500 张卡里缺什么 |
| `insight` | ✔ | 10-80 字，能提炼成哪条口径 |
| `verdict` | ✔ | `keep`（值得转卡）/ `dup`（库里已有，填 `dup_of`）/ `reject`（看过了但不该进，填 `reject_reason`）/ `promoted`（已经转成卡了） |

`check` 会把每条 `keep` 候选在库里的两张「最近邻」列出来（共同词是什么），但**它只提示，不裁决**。一句话的情境做自动查重不可靠，判断交给你：点开那张卡看一眼，像不像同一个情境。

`seen.jsonl` 记「我读过什么」，一行一条：`date` / `topic` / `url` / `title` / `note`。它的作用是让 `plan` 知道最近别重复搜，也是这个仓库唯一能公开追溯的来源账本。

## 五条口径

1. **只提炼结构，不搬句子。** 卡里的 `examples` 必须是你自己写的。抄来的句子在真实对话里一定走样，而且涉及版权。
2. **一条素材最多提炼一张卡。** 一条内容能覆盖三个情境，说明它太泛，通常说明它没用。
3. **不收「劝分」「他不爱你」这类结论。** 小红书情感帖评论区的大量内容是劝分（有媒体报道过这个现象），那套话术的结论是「离开」，本仓库的立场是「先把这句话说好」，方向相反。看到这类内容，`verdict=reject`。
4. **不收具体的人。** 真实姓名、学校、公司、聊天截图里的头像和 ID 一律不进仓库，写素材时也不要抄。
5. **没有 `gap` 就不要 `keep`。** 「这个情境挺好」不够，得说出 500 张卡里哪一张差在哪。写不出缺口，说明它只是让你有共鸣，不是库缺东西。

## 抓不到的时候：缺口清单

还有一种更急的情况：用户此刻问的事，库里一张卡都对不上。这时不是等「每天十分钟」，是当场找：

```bash
python scripts/find.py "她的原话"          # 猜场景 + 出检索词 + 给提炼模板
python scripts/find.py "她的原话" --note   # 顺手记进 ~/.crush-reply/gaps/<日期>.md
```

`gaps/` 是一份流水帐，一行一条，只记「哪天、哪个场景、什么情况」。它不参与 CI 校验，也不需要格式整齐——它的用处是让「库里没有」这件事留下痕迹。攒到同一类出现三次，就值得补一张卡；一次都没重复过的，通常是个例，不用管。

`find.py` 不联网。它只负责把一个人的原话变成能丢进搜索框的词，搜和读仍然由模型来做，口径跟上面的五条完全一样。

## 不做什么

- **不抓取、不爬。** 小红书和抖音的公开接口没有、反爬强，抓下来的东西带版权和隐私风险。这个目录里的每一条都是人（或模型）读过之后写的一句话，不是批量下载。
- **不追求量。** 一天 2-3 条，一个月 60-90 条，能转成 10 张卡就是好收成。攒 500 条没人转的候选等于没做。
- **不联网的脚本。** `harvest.py` 只做轮转、校验、查重；搜索是调用它的那个模型干的活。

## 三个月后这个目录长什么样

`seen.jsonl` 三五百行，`inbox/` 十来个文件，其中三分之一 `reject`——那三分之一才是最有价值的部分，它记录了「哪些看起来很动人的说法，其实是不能学的」。
